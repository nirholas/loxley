x402 on Robinhood Chain · eip155:4663 · USDG

The payment rail agents use on Robinhood Chain.

Robinhood Chain shipped with a stablecoin that has no EIP-3009 and no EIP-2612, so every x402 payment on it runs through Permit2, and until now through one hosted facilitator at a time. Loxley is the open rail: a self-hostable facilitator, a router that fails over between facilitators, a settlement explorer, an escrow with attested refunds, and ERC-8004 agent identity. All of it on the canonical contracts, all of it Apache-2.0.

What was missing

The reference x402 SDKs know Base and Solana. Robinhood Chain had facilitators, but no rail.

Clients refused to pay

USDG is not a registered default asset, so a stock reference client rejects a 4663 quote before it ever signs. Loxley registers it upstream and ships the runtime shim until that lands.

One facilitator, one point of failure

Every seller pointed at a single hosted verify/settle endpoint. The router scores facilitators by latency and benches the ones that fail, without ever retrying a settle that might have landed.

No approval path for fresh wallets

Without EIP-2612 a payer needs one on-chain approve() and the ETH to pay for it. The facilitator grants exactly that gas to wallets that hold USDG and nothing else.

Nobody could see the economy

Eleven thousand settlements had happened on the canonical proxy with no explorer. Loxley Scan indexes every one and ranks facilitators, payees and payers.

Bad responses were just losses

A paid call that returns garbage was unrecoverable. The escrow holds the exact price until an attestor signs a receipt, and refunds on rejection or silence.

Agents had no identity here

ERC-8004 registries exist on Base and Arbitrum. Loxley deploys the reference registries deterministically to 4663 and 46630.

Quickstart

Three sides of a payment. Each is a few lines on top of the reference x402 packages.

buyer

Pay a 402 in USDG

Wrap fetch. The first call on a fresh wallet needs a one-time Permit2 approval, which the SDK sends for you.

import { createWalletClient, http, publicActions } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { robinhoodChain, createRobinhoodPayer, ensurePermit2Approval } from "@loxley/sdk";

const wallet = createWalletClient({ account: privateKeyToAccount(KEY), chain: robinhoodChain, transport: http() }).extend(publicActions);
await ensurePermit2Approval(wallet, "eip155:4663");
const pay = createRobinhoodPayer(wallet);
const quote = await pay("https://quotes.example/aapl");
seller

Charge for an endpoint, with failover

Drop the router in where a single facilitator URL used to go. It merges /supported across facilitators and routes by health.

import { x402ResourceServer } from "@x402/core/server";
import { ExactEvmScheme } from "@x402/evm/exact/server";
import { FacilitatorRouter, KNOWN_FACILITATORS, registerRobinhoodMoneyParser } from "@loxley/sdk";

const server = new x402ResourceServer(new FacilitatorRouter(KNOWN_FACILITATORS, { requireNetwork: "eip155:4663" }));
server.register("eip155:*", new ExactEvmScheme());
registerRobinhoodMoneyParser(server); // "$0.01" now means 10000 atomic USDG on 4663
operator

Run your own facilitator

One key with a little ETH. It journals every verify and settle, catalogs Bazaar declarations, and replays receipts instead of re-broadcasting.

git clone https://github.com/nirholas/loxley && cd loxley && pnpm install
cp .env.example .env   # set FACILITATOR_PRIVATE_KEY
pnpm facilitator       # http://localhost:4663/supported

Facilitator

The reference @x402/core facilitator with everything an operator actually needs around it.

schemes

exact and upto on 4663 and 46630

Permit2 witness settlements through the audited canonical proxies. ERC-20 approval gas sponsoring for tokens without EIP-2612, which on this chain is the only kind.

safety

Idempotent settle

Every settle is keyed on a canonical hash of the signed payload. A retry after a timeout returns the original receipt instead of broadcasting twice.

discovery

Persisted Bazaar catalog

Sellers that declare the discovery extension are catalogued on first verified payment and served at /discovery/resources with search, type filters and settle counts.

onboarding

Approval gas grants

POST /gas-grant sends a fresh USDG holder exactly the ETH for one approve(). Once per address, only while unapproved, only while the facilitator holds its reserve.

ops

/health, /stats, /metrics

Signer balances and block heights per network, settlement and verification counters, settled volume by asset, in JSON and Prometheus text.

tested

End to end on a fork

pnpm --filter @loxley/facilitator e2e forks mainnet with anvil, funds a payer with real USDG, pays through the reference client, settles, replays, and grants gas.

SDK

@loxley/chain is the registry. @loxley/sdk is the router and the payer.

@loxley/chain

Chain 4663 as data

viem chain definitions, USDG and Permit2 addresses, the canonical proxy addresses, a strict USD to atomic parser, and a money parser that teaches any x402 resource server what a dollar means here.

FacilitatorRouter

Health-scored failover

EWMA latency, consecutive-failure benching with cooldown, network-aware candidate filtering from merged /supported. Verify fails over freely; settle only on pre-broadcast transport errors.

createRobinhoodPayer

fetch that pays

The reference exact EVM client registered for both networks, with spend controls opened for USDG so a stock client stops rejecting 4663 quotes.

Loxley Scan

The settlement explorer. Indexes settle() and settleWithPermit() on the canonical proxies, decodes payer, payee, facilitator and amount from calldata and receipts, and ranks everyone.

indexer

Log windows with backoff

Runs on the public RPC with 20k-block windows and exponential backoff, or on Alchemy with bigger ones. Cursor-based, resumable, idempotent inserts.

api

JSON for everything

/api/overview, /api/settlements, /api/facilitators, /api/payees, /api/payers, /api/daily, /api/status. Filter settlements by any party.

ui

Server-rendered, no build

Overview tiles, a 30-day chart, leaderboards, per-address pages split by role, per-transaction detail with gas cost in ETH.

LoxleyEscrow

Per-request escrow with an attested release. Non-upgradeable, no admin, no pause.

open(permit, payer, EscrowWitness{requestId, payee, attestor, deadline, schemaHash}, signature)
   payer signs one Permit2 witness transfer; the facilitator submits it; funds sit in the contract
release(Receipt{requestId, responseHash, status, accepted: true}, attestorSig)   -> payee (minus feeBps)
refund (Receipt{..., accepted: false}, attestorSig)                            -> payer
reclaim(requestId)   after deadline, anyone                                    -> payer

13 unit tests against the real Permit2 bytecode, a fuzz invariant on value conservation, and a fork test against live USDG on 4663. Deploys deterministically to the same address on mainnet and testnet through the Arachnid CREATE2 deployer.

Agent identity

The ERC-8004 reference registries (Identity, Reputation, Validation) deployed to Robinhood Chain with deterministic addresses, plus a testnet USDG with a built-in faucet so a hackathon team spends day one on product.

forge script script/DeployAgentRegistries.s.sol --rpc-url $RHC_TESTNET_RPC_URL --broadcast
forge script script/DeployMockUSDG.s.sol         --rpc-url $RHC_TESTNET_RPC_URL --broadcast   # testnet only, refuses 4663
cast send $MOCK_USDG "drip()" --rpc-url $RHC_TESTNET_RPC_URL                                   # 1,000 USDG per day per address
